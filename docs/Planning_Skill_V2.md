# Outlook 自动工作包排期 Skill (Work Package Auto-Scheduling Skill v2.0)

## 1. 适用场景
当用户提供包含工作包（Work Packages）及预估工时（Time）的列表或 Excel/CSV 表格，并要求结合其 Outlook 日历自动排定工作计划、输出文字版日程及 `.ics` 批量导入代码时，严格调用并遵循本 Skill 规则。

---

## 2. 核心排期规则 (Core Rules)

### 2.1 输入表格列解析规则 (Excel / CSV Schema)
* **A 列（Main Milestone）**：仅给用户查看的里程碑分组信息，**排期计算时直接忽略**，严禁将其误识别为工作包。
* **B 列（Prefix）**：项目/模块前缀字段（如 `UBSW02`，实际使用时可能替换为其他字段；若仅首行填写则默认向下填充至所有行）。排期输出及生成 `.ics` 日历代码时，**必须在所有日程主题（Subject / SUMMARY）最前面加上 `[Prefix]` 标注**（例如：`[UBSW02] Module CCB`）。
* **C 列（Work Packages）**：工作包具体名称，严格按照表格自上而下的行序依次排期。
* **D 列（Time）**：对应工作包所需的总工时（如 `2h`, `16h`）。

### 2.2 动态起始日期与工作窗口 (Dynamic Start & Working Hours)
* **动态“明天”起点**：排期必须从**用户发送消息当天的第二天（即“明天”）**开始起算（严禁写死固定日期）。若第二天为周六或周日，则自动跳过周末，从下一个周一正式开始排期。
* **工作日限制**：仅在**周一至周五**排期，自动跳过周末（周六、周日）。
* **每日工作窗口**：`08:00 - 17:00`（以用户所在时区 `Asia/Shanghai` UTC+8 为准）。
* **午休排除**：每日 `12:00 - 13:00` 固定为午休时间，**严禁安排任何工作包**。
* **每日理论最大可用时长**：扣除午休后，每天最多有 8 小时工作窗口（上午 `08:00 - 12:00` 共 4h，下午 `13:00 - 17:00` 共 4h）。

### 2.3 实时日历冲突与自留时间避让 (Calendar Conflict & Self-Booking Avoidance)
* **实时查询**：每次排期必须实时调用 Outlook 日历接口拉取从“明天”起算的完整日程。
* **全面避让已占用时段（含自留日程）**：
  * 日历中在工作窗口（`08:00 - 17:00`）内的**所有常规会议**，以及**用户自己提前 Book、预留或之前已导入的所有个人工作安排（Self-appointment / 已导入的工作包日程）**，均**必须视为已占用时间**，严禁在这些时段重复排入新任务。
* **仅忽略的非阻塞项**：
  * 自动忽略已取消的会议（标题含 `Canceled:` / `Cancelled:`）。
  * 自动忽略同事的休假/外出/居家办公全天提醒（如 `OoO`、`Out of Office`、`on Leave`、`HO`）以及节气/节假日全天提醒（如 `Hoar-Frost Falls`、`Winter Begins` 等时长 $\ge 24\text{h}$ 的全天事件）。

### 2.4 任务排期最小粒度 (Granularity & No-Splitting)
* **整小时原则**：排期最小时间单位为 **1 小时（整小时）**，严禁将 1 小时拆分为两个 0.5 小时。
* **碎片时间处理**：若因 `:30` 或 `:45` 开始/结束的会议导致产生不足 1 小时的碎片时间（如 `09:00 - 09:30`、`13:45 - 14:00`），该碎片时间**不可用于排工作包**，直接归入当日的弹性空余时间。

### 2.5 每日弹性缓冲预留 (Daily Buffer Time)
* **至少 1 小时空余**：在每天扣除会议、自留占用时段和午休后的可用工作时间中，**必须至少预留 1 小时（$\ge 1\text{h}$）的空余时间**不排任务（可由半小时碎片时间累加，或直接留出整小时空档）。
* 即：`当日排期工作包总时长 <= 当日无占用总时长 - 1h`，且所有工作包时段必须为连续整小时。

---

## 3. 标准执行步骤 (Execution Workflow)

1. **读取并解析工作包文件**：忽略 A 列，提取 B 列前缀 `[Prefix]`，按顺序读取 C 列工作包名称与 D 列所需工时，计算总工作包数量与总工时。
2. **拉取并清洗实时 Outlook 日历**：从用户发信时间的次日起拉取日历视图，转换至本地时区（`UTC+8`），过滤全天非阻塞提醒与已取消会议，保留所有日间常规会议与用户自留/已导入日程作为不可用时段。
3. **逐日计算可用整小时槽位**：按日扫描 `08:00 - 12:00` 与 `13:00 - 17:00`，剔除所有已占用时段后，提取整小时时间块，并确保当日未排任务的空闲时间（含碎片时间）总和 $\ge 1\text{h}$。
4. **顺序分配与同日连续合并**：按照工作包列表顺序填入可用整小时槽位；若同一工作包在同一天被分配在连续的整小时槽位（如 `08:00-09:00` 和 `09:00-10:00`），自动合并为一个连续时段（`08:00-10:00`），并标注累计进度（如 `(2/8h)`）。

---

## 4. 标准输出格式 (Output Format)

每次排期响应必须完整包含以下四个部分：

1. **核心结论**：说明起始排期日期、前缀标识、总工作包数量、总工时、跨越工作日天数以及预计最终完成日期与时间。
2. **每日详细排期表（按天展示）**：
   * **日期与星期**
   * **Outlook 已占用时段（会议及自留安排）**：列出当天在工作窗口内的所有已有会议及用户自留日程
   * **工作包安排**：列出具体整小时时间段、`[Prefix] 工作包名称`、当日投入时长及累计进度（如 `进度 3/8h` 或 `已完成 ✅`）
   * **今日预留空余**：明确展示当天预留出的 $\ge 1\text{h}$ 缓冲时间段
3. **工作包完成时间总览表（Markdown 表格）**：汇总每个工作包的序号、`[Prefix] 工作包名称`、总工时、计划执行日期及具体时间段。
4. **可批量导入的 `.ics` 日历代码**：在代码块中直接输出完整的标准 RFC 5545 `.ics` 文件内容（包含 `TZID=Asia/Shanghai`、带有 `[Prefix]` 的 `SUMMARY` 及进度描述），供用户直接复制保存为 `.ics` 文件后双击批量导入 Outlook。
